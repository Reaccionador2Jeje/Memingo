# Memingo HTTP Server API

Memingo provides a native `.mgo` API and a Python application API, alongside the static-file server.

## Native Memingo API

Start the included native example from the repository root:

```bash
python -m memingo api examples/native_api.mgo
```

Open `http://127.0.0.1:8000/`, try `/hello/Cris`, or send JSON to `POST /echo`.

Create a server in any `.mgo` file:

```mgo
vibe app = api()

ritual home(request) {
    drop {name: "Memingo", status: "ready"}
}

ritual greet(request) {
    drop {message: "Hello " + request.params.name}
}

ritual echo(request) {
    drop {received: request_json(request)}
}

api_get(app, "/", home)
api_get(app, "/hello/<name>", greet)
api_post(app, "/echo", echo)
api_listen(app)
```

Available built-ins:

- `api()` creates a server application.
- `api_get(app, path, ritual)`, `api_post(...)`, `api_put(...)`, `api_patch(...)`, and `api_delete(...)` register routes.
- `api_route(app, methods, path, ritual)` registers one or more HTTP methods.
- `request_json(request)` parses the incoming JSON body.
- `response_json(data, status?, headers?)` creates a JSON response.
- `response_text(text, status?, headers?)` creates a plain-text response.
- `response_html(html, status?, headers?)` creates an HTML response.
- `response_redirect(location, status?)` creates a redirect (301, 302, 303, 307, or 308).
- `response_error(status, message)` creates a JSON error response for status codes 400–599.
- `api_use(app, ritual)` registers middleware. The ritual receives `(request, next)`.
- `response_header(response, name, value)`, `response_status(response, status)`, and `response_body(response, body)` modify the response returned by `next()`.
- `api_listen(app, host?, port?)` starts the server.

The request passed to a ritual is an object with `method`, `path`, `query`, `params`, `headers`, and `body` fields. Route handlers may return an object or list for a JSON response, text for a text response, or `ghost` for HTTP 204. Invalid request JSON returns HTTP 400.

Middleware runs in registration order before the route. Call `next()` to continue, or return an object to short-circuit the request. When `next()` returns a response, use the response helpers to modify it and return it.

```mgo
ritual add_server_header(request, next) {
    vibe response = next()
    response_header(response, "X-Powered-By", "Memingo")
    response_status(response, 200)
    drop response
}

api_use(app, add_server_header)
```

The default host is `127.0.0.1`. CLI flags `--host` and `--port` override the defaults supplied by `api_listen(app)`. Route-ritual and middleware execution is serialized to protect shared interpreter state across concurrent HTTP requests.

## Native response helpers

Route rituals can use response constructors when they need to control the HTTP status, content type, or headers instead of returning a plain object or string:

```mgo
ritual create_item(request) {
    drop response_json({id: 42, state: "created"}, 201, {"X-API": "Memingo"})
}

ritual old_page(request) {
    drop response_redirect("/new-page", 308)
}

ritual missing(request) {
    drop response_error(404, "Item not found")
}
```

## Forms and file uploads

The native API and Python request object support URL-encoded forms and multipart uploads.

Native `.mgo` example:

```mgo
ritual upload(request) {
    vibe fields = request_form(request)
    vibe files = request_files(request)
    when headcount(files) == 0 {
        drop response_error(400, "Choose a file")
    }
    vibe saved = save_upload(files[0], "uploads")
    drop response_json({title: fields.title, file: saved}, 201)
}
```

The included `examples/native_uploads.mgo` provides a complete HTML upload form. Run it with:

```bash
python -m memingo api examples/native_uploads.mgo
```

Open `http://127.0.0.1:8000/`, choose a file, and submit the form.

- `request_form(request)` returns parsed form fields.
- `request_files(request)` returns uploaded file records. Each record includes `field`, `filename`, `content_type`, `size`, and binary `data`.
- `save_upload(file, directory?)` stores an uploaded file under a directory inside the current project and returns its generated filename, original filename, relative path, size, and content type.
- Python handlers can use `request.form()` and `request.files()` directly.

Safety limits: the HTTP server accepts request bodies up to 10 MB and individual files up to 5 MB. Saved filenames are generated by Memingo; user-supplied path components are discarded. Upload directories must remain inside the project. The server does not provide authentication or virus scanning: validate file types and permissions in your application, and do not expose an upload endpoint publicly without adding appropriate access controls.

## Python API quick start

A runnable Python example is included in `examples/api.py`. Start it with:

```bash
python -m memingo api examples/api.py
```

Then open `http://127.0.0.1:8000/` or try `/hello/Cris`.

## Create an API

Create `app.py`:

```python
from memingo import MemingoApp, Response, serve_app

app = MemingoApp()

@app.get("/")
def home(request):
    return {"name": "Memingo API", "status": "based"}

@app.get("/users/<user_id>")
def get_user(request):
    return {
        "id": request.params["user_id"],
        "search": request.query,
    }

@app.post("/echo")
def echo(request):
    return Response.json({"received": request.json()})

@app.put("/notes/<note_id>")
def update_note(request):
    data = request.json()
    return Response.json({"id": request.params["note_id"], "note": data})

@app.delete("/notes/<note_id>")
def delete_note(request):
    return Response("", status=204)

@app.use
def add_server_header(request, next_handler):
    response = next_handler()
    response.headers["X-Powered-By"] = "Memingo"
    return response

if __name__ == "__main__":
    serve_app(app, host="127.0.0.1", port=8000)
```

Run it with Python:

```bash
python app.py
```

Or use the Memingo launcher from the project directory:

```bash
memingo api app.py --host 127.0.0.1 --port 8000
```

The launcher imports `app.py`, checks that it exports an `app` instance of `MemingoApp`, and starts the API. The default bind address is local-only (`127.0.0.1`). The API listens on `http://127.0.0.1:8000`. Use `host="0.0.0.0"` only when you intentionally want other devices on your network to reach the server; use an appropriate firewall and do not expose development services to the public internet.

## Routes

- `@app.get(path)`
- `@app.post(path)`
- `@app.put(path)`
- `@app.delete(path)`
- `@app.route(path, methods=("GET", "POST"))`

Path parameters use angle brackets, for example `/users/<user_id>`.

## Request

A route receives a `Request` object:

- `request.method`, `request.path`
- `request.params` for path parameters
- `request.query` for query-string values
- `request.headers`
- `request.body`
- `request.text()`
- `request.json()`
- `request.form()` for URL-encoded or multipart fields
- `request.files()` for uploaded file metadata and binary data

Invalid JSON returns an HTTP 400 response.

## Response

A route can return a string, dictionary, list, `None`, or a `Response`:

- strings become text responses
- dictionaries and lists become JSON responses
- `None` becomes HTTP 204
- `Response.json(data, status=200, headers=None)`
- `Response.text(text, status=200, headers=None)`
- `Response(body, status=200, headers=None, content_type=...)`

Unmatched routes return 404. A matching route with an unsupported method returns 405 and an `Allow` header.

## Middleware

Middleware receives `(request, next_handler)`. Call `next_handler()` to continue to the next middleware and route. Middleware may inspect or modify the response.

## Static files

The existing static server remains available:

```bash
memingo serve public --host 127.0.0.1 --port 8000
```

The route-based API and static-file serving are separate entry points. Templates and hot reload are still planned.
